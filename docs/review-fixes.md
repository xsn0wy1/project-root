# Independent-review follow-up

Completed against the current Stage 6 checkout. All supplied findings were compared with the implementation; the remaining issues are corrected. Submission packaging stays separate. Detailed counts are in `review-fixes-verification.json`, with stage and cumulative measurements in `review-fixes-source-metrics.json` and `source-metrics.json`.

## Findings and resolutions

| Finding | Current resolution |
| --- | --- |
| Address lookup enabled against public demo providers | Configuration defaults and the example now disable lookup and leave both provider URLs empty. Removed the hardcoded public fallbacks. Lookup requires explicit configuration of trusted/self-hosted HTTPS endpoints; the existing unmapped fallback remains available. The isolated local configuration was already disabled and was not changed. |
| Successful logins consume the throttle; username-only lockout | Only invalid credentials consume the failure budget: 60 per IP and 10 per IP/normalized-username pair over 15 minutes. Successful logins clear their pair bucket without clearing the shared IP failure budget. There is no global username-only lock bucket. |
| Reset email delays the response and occupies a web worker | Flush the generic 202 and release the session before dispatch. A separate bounded PHP CLI process reads an atomically published private job, rechecks the current token/revision/eligibility/expiry, delivers, and removes the job. A failed older send cannot delete a newer reset token. Missing known worker/provider requirements produce the same 503 before account lookup. |
| Duplicate account approval/disable/list paths | Removed the unused HTTP actions and duplicate approval/disable functions. The UI and CLI share the versioned `accounts_manage()` implementation. A pending application cannot be disabled and remains approvable after a rejected attempt. |
| Password/session APIs have no UI | Settings now has a themed current/new/confirmation password dialog and an Active sessions menu/dialog. Users can revoke their other browsers or the current one. Successful password changes require a new login; failed requests retain input. Localized email recovery remains accessible. |
| Unused tracking control/history and routes get HTTP actions | Removed those HTTP actions. Keep scoped tracking snapshots, route directory operations and internal route reads needed by writes. Simulation controls remain CLI-only; shared fictional tracking, position history and pruning remain intact. |
| Ambulances bypasses shared module loading | Load its procedural module through `autoload.php`, like the other domains. |
| Views hardcode Spanish in HTML | Shared page rendering emits the saved staff locale or public language choice/Spanish default, including `Content-Language`. Removed the participant picker's hardcoded language. Browser language switching remains available. |
| Account/password revisions depend on Transfers | Revision validation now belongs to the existing core `Request::version()` helper. All affected callers were updated and the transfer-specific duplicate was removed. |
| HTML lacks framing protection | All 25 HTML pages send `Content-Security-Policy: frame-ancestors 'self'` and `X-Frame-Options: SAMEORIGIN`. Private binary response policies remain unchanged. |
| Google Fonts remains external | Bundle the original Inclusive Sans/Krub font bytes, face descriptors, weights and Unicode ranges locally, with source/hash records and SIL license notices. Five page profiles preserve the previous font selection; pages make no Google Fonts requests. Authentication pages retain their original fallback typography. |
| Unlimited current-password checks | Limit incorrect checks to five per user/source over 15 minutes, with further attempts returning 429 and Retry-After. Successful changes clear that bucket. Administrator resets retain their separate permission/revision checks. |
| Pending/disabled staff pages return raw JSON | Already corrected in this checkout: invalid staff status/session becomes an unauthenticated page request and redirects with 303. Added explicit regression checks for both pending and disabled accounts. API errors retain their existing JSON contract. |

Mail jobs contain temporary delivery credentials outside `public/`, in owner-only directories/files (0700/0600). No scheduler or framework is introduced. `backend/php/cli/send-reset-mail.php` can drain pending jobs manually. Deployment needs executable PHP CLI at `PHP_BINDIR` and `proc_open`; provider delivery uses bounded cURL requests with TLS verification and no redirects. Provider rejection logs omit addresses, tokens and response bodies. A 202 confirms the request, not inbox delivery.
